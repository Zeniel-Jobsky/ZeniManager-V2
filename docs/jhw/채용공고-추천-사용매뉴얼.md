# 채용공고 추천 기능 사용 매뉴얼

> 작성일: 2026-08-26
> 대상: 상담사, 개발·배포 담당자
> 적용 기능: 잡코리아·사람인·인크루트 채용공고 추천

## 1. 기능 개요

내담자 상세 화면의 `채용공고 추천` 탭에서 Supabase DB에 저장된 내담자의 `희망직종`을 기준으로 다음 세 사이트의 공개 채용공고를 조회합니다.

- 잡코리아
- 사람인
- 인크루트

조회 결과에서는 이미 마감된 공고를 제외하고, 같은 공고로 판단되는 결과는 하나로 합칩니다. 중복 공고가 여러 사이트에 있으면 한 카드에서 각 사이트의 원문 링크를 확인할 수 있습니다.

브라우저는 Edge Function에 내담자 ID만 전달합니다. 실제 검색어는 Edge Function이 요청 시점에 `public.clients.desired_job`을 다시 조회해 사용합니다.

## 2. 최초 배포 준비 — 운영자용

실제 Supabase DB에서 사용하려면 아래 작업이 먼저 완료되어야 합니다. 앱의 `VITE_SUPABASE_URL` 또는 설정 화면의 Supabase URL과 **같은 프로젝트**에서 작업해야 합니다.

### 2.1 RLS SQL 실행

SQL 파일은 PowerShell이 아니라 Supabase 대시보드의 `SQL Editor`에서 실행합니다.

1. Supabase 대시보드에서 사용할 프로젝트를 엽니다.
2. `SQL Editor` → `New query`를 선택합니다.
3. [supabase_user_rls.sql](../../supabase_user_rls.sql)의 전체 내용을 붙여넣고 `Run`을 누릅니다.
4. 성공한 다음 [job_recommendations_clients_rls.sql](../../supabase/sql/job_recommendations_clients_rls.sql)의 전체 내용을 새 쿼리에서 실행합니다.

반드시 위 순서대로 실행합니다. 두 번째 SQL에서 `duplicate counselors.auth_user_id` 오류가 나오면 상담사 계정 연결 데이터의 중복을 먼저 정리해야 합니다.

### 2.2 Edge Function 배포

프로젝트 루트에서 PowerShell을 열고 실행합니다.

```powershell
cd C:\Users\realhjung\Desktop\project\ZeniManager

& "C:\Program Files\nodejs\npx.cmd" supabase@latest login
& "C:\Program Files\nodejs\npx.cmd" supabase@latest projects list
& "C:\Program Files\nodejs\npx.cmd" supabase@latest link --project-ref 프로젝트_REF
& "C:\Program Files\nodejs\npx.cmd" supabase@latest functions deploy recommend-job-postings
```

프로젝트 REF는 Supabase 대시보드 주소의 `/project/` 다음 값입니다.

```text
https://supabase.com/dashboard/project/프로젝트_REF
```

배포 결과에 다음과 같은 메시지가 나오면 정상입니다.

```text
Deployed Functions on project ...: recommend-job-postings
```

인증된 상담사만 호출해야 하므로 `--no-verify-jwt` 옵션은 사용하지 않습니다. 자세한 함수 운영 정보는 [Edge Function README](../../supabase/functions/recommend-job-postings/README.md)를 참고합니다.

## 4. 희망직종 입력

### 기존 내담자 수정

1. 상담사 계정으로 로그인합니다.
2. 왼쪽 메뉴에서 `상담자 목록`을 엽니다.
3. 담당 내담자를 선택해 상세 화면으로 이동합니다.
4. `대시보드` 탭의 `희망 조건 상세` 카드로 이동합니다.
5. `희망직종` 항목에 마우스를 올리고 연필 아이콘을 누릅니다.
6. 희망직종을 입력한 후 체크 아이콘을 누르거나 `Enter`를 입력해 저장합니다.

여러 희망직종은 쉼표로 구분하며 최대 3개까지 검색됩니다.

```text
백엔드 개발자, Java 개발자, 서버 개발자
```

검색 품질을 위해 직종명만 간결하게 입력합니다. 이름, 전화번호, 이메일 등 개인정보는 넣지 않습니다. 직종 하나는 80자 이내로 입력하는 것을 권장합니다.

### 신규 내담자 등록

`상담자 목록` → `상담자 등록` 화면에서 희망직종 1~3을 입력하고 저장합니다. 저장된 값은 내담자 상세 화면의 `희망직종`에서 다시 확인할 수 있습니다.

## 5. 채용공고 조회

1. 희망직종이 입력된 내담자의 상세 화면을 엽니다.
2. `요약 및 분석`과 `챗봇` 사이의 `채용공고 추천` 탭을 누릅니다.
3. 탭이 열리면 공고 검색이 자동으로 시작됩니다.
4. 검색이 끝날 때까지 `검색 중...` 표시를 기다립니다.
5. `전체`, `잡코리아`, `사람인`, `인크루트` 필터로 사이트별 결과를 확인합니다.
6. 원하는 카드의 `사이트명에서 보기` 버튼을 눌러 원문 공고를 새 창에서 확인합니다.

각 카드에서는 다음 정보를 확인할 수 있습니다.

- 공고 출처와 마감일
- 공고 제목과 회사명
- 지역, 경력, 학력, 고용형태
- 해당 공고를 찾을 때 사용한 희망직종
- 잡코리아·사람인·인크루트 원문 링크

화면 오른쪽의 조회 시각은 결과를 가져온 기준 시각입니다.

## 6. 새로고침과 결과 해석

- `새로고침`은 최신 공개 공고를 다시 요청합니다.
- 연속 요청을 방지하기 위해 사용자·내담자별로 약 30초의 재요청 제한이 적용됩니다.
- 일반 조회 결과는 최대 약 10분 동안 캐시될 수 있습니다.
- `일부 사이트의 응답이 없어...` 안내가 표시되면 정상 응답한 사이트의 공고만 보여주는 상태입니다.
- 숫자가 표시된 사이트 필터를 누르면 해당 사이트의 결과만 볼 수 있습니다.
- 경고 아이콘이 표시되고 비활성화된 사이트는 그 조회에서 응답하지 못한 사이트입니다.
- `현재 추천할 수 있는 공고가 없습니다`가 나오면 해당 검색어에서 확인 가능한 마감 전 공고가 없다는 뜻입니다.

`상시채용`과 `채용시 마감`은 종료가 확인되지 않는 공고이므로 결과에 포함될 수 있습니다. 외부 사이트의 상태는 수시로 변경되므로 지원 전 반드시 원문에서 접수 가능 여부를 다시 확인합니다.

## 7. 실제 Supabase DB로 테스트

Supabase `SQL Editor`에서 다음 읽기 전용 쿼리를 실행해 테스트할 내담자를 찾습니다.

```sql
select
  c.id as client_id,
  c.name as client_name,
  c.desired_job,
  c.counselor_id,
  co.auth_user_id,
  u.user_name as counselor_name
from public.clients c
left join public.counselors co on co.id = c.counselor_id
left join public."user" u on u.user_id = co.auth_user_id
where nullif(btrim(c.desired_job), '') is not null
order by c.updated_at desc nulls last
limit 20;
```

조회 결과에서 다음 조건을 만족하는 행을 선택합니다.

- `desired_job`이 비어 있지 않음
- `counselor_id`가 존재함
- `auth_user_id`가 실제 로그인할 상담사 계정의 `auth.users.id`와 같음

해당 상담사로 로그인한 뒤 조회된 `client_id`의 내담자 상세 화면에서 `채용공고 추천` 탭을 엽니다.

정상 동작 기준은 다음과 같습니다.

- 화면에 DB의 최신 희망직종이 표시됨
- 잡코리아·사람인·인크루트 필터가 표시됨
- 결과 카드 또는 `현재 추천할 수 있는 공고가 없습니다` 안내가 표시됨
- 마감된 공고가 결과에 나타나지 않음
- 같은 공고가 여러 사이트에 있으면 한 카드의 여러 원문 링크로 합쳐짐
- 원문 버튼이 해당 채용사이트의 HTTPS 주소로 열림

## 8. 계정과 DB 연결 기준

상담사 계정과 내담자 담당 관계는 다음 ID 연결을 사용합니다.

```text
auth.users.id
  = public."user".user_id
  = public.counselors.auth_user_id

public.clients.counselor_id
  = public.counselors.id
```

`auth.users.id`와 `public.counselors.id`는 서로 다른 값입니다. `clients.counselor_id`에 인증 사용자 ID를 직접 저장하면 담당 내담자 조회와 채용공고 추천 권한 확인이 실패합니다.

## 9. 문제 해결

| 증상 또는 메시지 | 확인 및 해결 방법 |
|---|---|
| `Supabase가 설정되지 않아 채용공고를 조회할 수 없습니다.` | 앱 설정 화면의 Supabase URL과 Anon Key를 확인합니다. 현재 배포한 프로젝트와 같은 프로젝트여야 합니다. |
| `로그인이 필요합니다.` 또는 `로그인 세션이 만료되었습니다.` | 로그아웃한 뒤 다시 로그인합니다. 로그인 후에도 계속되면 브라우저를 새로고침합니다. |
| `희망직종을 먼저 입력해주세요` | 내담자 상세 `대시보드` 탭에서 희망직종을 입력하고 저장합니다. |
| `희망직종 입력이 너무 깁니다.` | 직종별 입력을 80자 이내로 줄이고 최대 3개만 사용합니다. |
| `희망직종에 ... 개인정보 형식이 포함되어 있습니다.` | 이름, 전화번호, 이메일 등을 삭제하고 직종명만 입력합니다. |
| `내담자 정보를 찾을 수 없습니다.` | 로그인 상담사의 `counselors.auth_user_id`와 내담자의 `clients.counselor_id` 연결, 그리고 두 RLS SQL의 실행 여부를 확인합니다. |
| `n초 후에 다시 새로고침해주세요.` | 새로고침을 반복하지 말고 안내된 시간만큼 기다린 후 다시 시도합니다. |
| 일부 사이트의 결과만 표시됨 | 해당 사이트가 일시적으로 403, 429, CAPTCHA 또는 응답 지연을 반환한 상태일 수 있습니다. 잠시 후 새로고침합니다. |
| `세 채용사이트에서 공고를 가져오지 못했습니다.` | 네트워크와 Supabase Function 로그를 확인하고 잠시 후 재시도합니다. 반복되면 세 사이트의 검색 HTML 구조가 변경됐는지 확인합니다. |
| Edge Function을 찾을 수 없거나 호출이 실패함 | `recommend-job-postings`가 앱과 동일한 Supabase 프로젝트에 배포됐는지 확인합니다. |
| 상담자 목록에는 데이터가 없는데 `dev` 브랜치에서는 보임 | 현재 앱이 같은 Supabase 프로젝트를 사용하는지 확인하고, A→C 계정 매핑과 `clients` RLS를 점검합니다. |

Edge Function 실행 로그는 Supabase 대시보드의 `Edge Functions` → `recommend-job-postings` → `Logs`에서 확인합니다.

## 10. 배포 전 검증 — 개발자용

```powershell
pnpm test
pnpm check
pnpm check:edge
pnpm build
```

실제 세 채용사이트를 호출하는 선택 테스트는 다음과 같이 실행합니다.

```powershell
$env:LIVE_SCRAPE = '1'
pnpm vitest run supabase/functions/_shared/job-postings/job-postings.live.test.ts
Remove-Item Env:LIVE_SCRAPE
```

실사이트 테스트는 외부 사이트에 실제 요청을 보내므로 반복 실행하지 않습니다. CAPTCHA나 접근 제한을 우회하지 않으며, 운영자는 각 사이트의 이용약관과 `robots.txt`, 허용 호출 빈도를 주기적으로 확인해야 합니다.
