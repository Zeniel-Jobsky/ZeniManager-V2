# UX Flow — ZeniManager

> 작성자: BE-wookhyun (Claude Code와 함께 진행)
> 관련 문서: [0825-results.md](./0825-results.md), [기능테스트.md](./기능테스트.md)

각 단계마다 **필수사항**(이 단계가 동작하려면 DB/계정에 미리 갖춰져 있어야 하는 것)과 **필요사항**(그 순간 사용자가 입력하거나 시스템이 갖고 있어야 하는 값)을 구분해서 적는다.

---

## 1. 로그인

로그인 페이지에서 이메일, PW를 입력하여 로그인을 한다.

- **필수사항**: 사용자 정보가 Supabase Authentication에 등록되어 있어야 하고, `counselors`, `public.user` 테이블에도 등록되어 있어야 한다. (`counselors.auth_user_id`와 `public.user.user_id`가 둘 다 해당 Auth 계정의 UUID와 연결되어 있어야 함 — 하나라도 빠지면 로그인은 되지만 프로필/권한이 정상 동작하지 않음)
- **필요사항**: 로그인을 할 때 Supabase URL과 Supabase Anon Key가 있어야 한다.

---

## 2. 로그인 후 역할별 대시보드 이동

로그인에 성공하면 `/`으로 이동하고, 역할에 따라 자동으로 `/admin/dashboard`(관리자) 또는 `/dashboard`(상담사)로 리다이렉트된다.

- **필수사항**: `public.user.role`이 정확히 설정되어 있어야 한다 (4=관리자, 5=상담사). 값이 없거나 다르면 상담사로 취급된다.
- **필요사항**: 없음 (로그인 세션만 있으면 됨)

---

## 3. 상담사 업무 대시보드 (`/dashboard`)

사이드바 "업무 대시보드" 하위 메뉴 4개가 전부 같은 페이지(`Dashboard.tsx`) 안의 탭/섹션이고, URL만 다르게 진입한다.

### 3-1. 업무 현황 (`/dashboard`)

통계 카드(총 고객/진행중/취업완료/후속관리 필요/평균 점수/점수 분포)와 월별 등록·상담 추이 그래프를 확인한다.

- **필수사항**: 로그인 계정이 `counselors.auth_user_id`에 연결되어 있어야 한다 (연결 안 되면 담당 고객이 0명으로 집계됨). `clients_select`/`sessions_select` RLS 정책이 정상 설정돼 있어야 한다.
- **필요사항**: 없음 (조회 전용)
- **참고**: "취업완료" 관련 집계는 `isEmploymentCompletedStage()` 헬퍼로 "취업" 포함 값을 전부 잡는다 (정확히 "취업완료"라는 문자열만 세지 않음).

### 3-2. 상담자 검색 (`/dashboard/search`)

같은 업무 현황 화면에서 검색창에 이름/전화번호/희망직무를 입력해 본인 담당 고객을 빠르게 찾는다.

- **필수사항**: 3-1과 동일 (RLS가 본인 담당 고객만 결과로 반환).
- **필요사항**: 검색어 2글자 이상 입력.

### 3-3. 캘린더 (`/dashboard/calendar`)

월별 상담 일정 개수를 캘린더에 표시하고, 날짜를 클릭하면 해당 일자의 상담 목록을 보여준다.

- **필수사항**: 3-1과 동일한 RLS 조건. `sessions` 테이블에 `date` 값이 있어야 표시됨.
- **필요사항**: 없음 (조회 전용)

### 3-4. 메모장 (`/dashboard/memo`)

상담사 본인만 보는 개인 메모를 작성/조회한다.

- **필수사항**: `public.user`에 로그인 계정의 행이 있어야 함 (메모가 `public.user.memo` 컬럼에 저장되기 때문 — `counselors` 연결과는 별개로 `public.user` 자체가 없으면 저장 시 재조회 검증에서 실패함).
- **필요사항**: 없음 (텍스트 입력 후 저장)

---

## 4. 관리자 사업 대시보드 (`/admin/dashboard`)

KPI, 차트, 지점별 테이블로 구성된 관리자 전용 통합 대시보드. 지점/사업유형 필터로 전체 데이터를 좁혀볼 수 있다.

- **공통 필수사항**: 로그인 계정의 `public.user.role = 4`(관리자)여야 접근 가능. `is_admin()` RLS 정책이 이 계정을 관리자로 인식해야 전체 고객 데이터가 조회됨 (`public.user.role`뿐 아니라 `counselors.role`도 4로 맞춰져 있어야 함 — 두 테이블의 role이 따로 관리되므로 하나만 바꾸면 화면 접근은 되는데 데이터가 안 보이는 경우가 생김).

### 4-1. KPI 카드 + 지점/사업유형 필터

총원/진행중/취업완료/성사율 카드를 보고, 상단 필터로 특정 지점·사업유형만 좁혀본다.

- **필요사항**: 없음 (필터는 선택사항)

### 4-2. 프로세스 단계별 인원 차트

- **필요사항**: 없음
- **⚠️ 예외**: 참여단계 실제 값이 30여 종인데 이 차트는 아직 5개 고정 버킷(초기상담/심층상담/취업지원/취업완료/사후관리)만 집계해서, 그 외 값을 가진 고객 대부분이 차트에서 빠진다. 버킷팅 방향(5단계로 뭉치기 vs 실제 값 그대로) 결정 대기 중 (0825-results.md 10번 항목 참고).

### 4-3. 월별 성사율 추이

최근 6개월간 취업지원 종료일 대비 취업일자 기준으로 월별 성사율을 계산한다.

- **필요사항**: 없음 (고객의 `support_end_date`/`employment_date` 값이 있어야 정확히 계산됨)

### 4-4. 사업유형별 파이차트

- **필요사항**: 없음 (`business_type` 값 기준 분포)

### 4-5. 지점/상담사별 실적 테이블

지점(또는 특정 지점 선택 시 상담사)별 담당 인원/취업완료/성사율을 표로 본다.

- **필요사항**: 없음

---

## 5. 고객(상담자) 목록 조회 — 상담사용

로그인한 상담사 본인이 담당하는 고객만 목록에 보인다 (관리자는 전체 조회).

- **필수사항**: `counselors.auth_user_id` 연결 + `clients.counselor_id`가 해당 `counselors.id`를 정확히 가리키고 있어야 함. 데이터 개수와 무관하게 전체를 가져오도록 페이지네이션 처리되어 있음(1000건 제한 없음).
- **필요사항**: 없음

---

## 6. 고객 신규 등록

이름/연락처/주민번호 등 정보를 입력하고 등록 버튼을 누른다.

- **필수사항**: 로그인 계정이 `counselors`에 연결되어 있어야 한다 (연결 안 되면 `counselor_id`가 null로 저장 시도되어 RLS 위반 에러 발생).
- **필요사항**: 이름, 연락처, 주민번호(앞/뒤)는 필수 입력. 참여단계를 "취업" 관련 값으로 등록하는 경우 취업처 입력이 필수. `seq_no`(전체 최댓값+1)/`year`(등록 당해 연도)는 자동으로 채워짐.
- **등록 직후 부가 동작**: 참여단계가 취업 관련 값이면 취업 성공사례 AI 동기화(`syncEmploymentSuccessCase`)가 자동 트리거됨 (실패해도 등록 자체는 성공 처리, 경고 토스트만 뜸).

---

## 7. 고객 상세 조회 / 인라인 수정

목록에서 고객을 클릭해 상세 화면으로 이동, 각 필드를 클릭해 바로 수정한다.

- **필수사항**: 본인이 담당한 고객이거나 관리자 계정이어야 RLS를 통과한다.
- **필요사항**: 없음 (필드별로 즉시 저장)
- **참고**: 참여단계는 실제 값이 30여 종에 달해 드롭다운이 아니라 자유 텍스트로 입력받는다. 참여단계·취업처·취업직무·급여·취업일자 등을 취업 관련 값으로 바꾸면 취업 성공사례 동기화가 같이 트리거된다.

---

## 8. 상담 이력(세션) 등록/수정/삭제

고객 상세의 "상담이력"/"상담입력" 탭에서 상담 기록을 남긴다.

- **필수사항**: 로그인 계정이 `counselors`에 연결되어 있어야 함(세션도 `counselor_id`가 `counselors.id`를 참조하기 때문).
- **필요사항**: 상담 유형, 일자, 내용 입력. (회차/시작·종료시간/심층상담 프로파일링 점수 등은 DB에 컬럼이 없어 입력 UI 자체가 없음)
- **부가 동작**: 상담 유형에 따라 고객의 참여단계가 자동으로 업데이트된다 (예: "취업완료" 유형 기록 시 참여단계도 취업완료로 변경).

---

## 9. 취업 성공사례 AI 매칭 조회

고객 상세에서 유사한 취업 성공사례를 AI가 찾아 보여준다 (임베딩 기반 유사도 검색).

- **필수사항**: Edge Function(`sync-employment-success-case`, `search-employment-success-case`)이 최신 스키마로 배포되어 있어야 함. `employment_success_case` 테이블·RPC가 uuid 기준으로 마이그레이션되어 있어야 함.
- **필요사항**: 설정 화면에 OpenAI API Key가 등록되어 있어야 함 (임베딩 생성용). 대상 고객의 취업처(employer) 값이 있어야 동기화가 진행됨.

---

## 10. 관리자 — 상담사 목록 조회 / 관리자 메모

상담사별 담당 인원, 취업완료 인원, 성취율을 확인하고 개인 메모를 남긴다.

- **필수사항**: 로그인 계정의 `public.user.role = 4`(관리자)여야 화면 접근 가능. `manager_memo` 테이블이 존재해야 메모 기능이 동작함.
- **필요사항**: 없음 (조회는 자동, 메모는 텍스트 입력 후 저장)

---

## 11. 관리자 — 전체 고객 목록 / CSV 내보내기

지점·참여단계로 필터링해 전체 고객을 조회하고, CSV로 내보낸다.

- **필수사항**: `public.user.role = 4`(관리자).
- **필요사항**: 없음 (내보내기는 즉시 다운로드)
- **⚠️ 예외**: 엑셀/CSV **가져오기(임포트)**는 아직 옛 스키마 필드명을 참조하고 있어 정상 동작하지 않음 (기능테스트.md 🔴 참고).

---

## 12. 설정 화면 — Supabase 연결 정보 입력

앱 최초 실행 시 또는 연결 정보 변경 시 Supabase URL/Anon Key/(관리자는) Service Role Key, OpenAI Key를 입력한다.

- **필수사항**: 없음 (최초 설정 화면 자체는 로그인 없이도 접근 가능)
- **필요사항**: Supabase 프로젝트 URL, Anon Key. 관리자 기능(상담사 계정 생성 등)을 쓰려면 Service Role Key도 필요. AI 기능을 쓰려면 OpenAI API Key 필요.

---

## 부록: 계정 하나가 정상 동작하려면 필요한 DB 연결 관계

로그인부터 고객 등록까지 전 과정에서 실제로 얽히는 테이블 관계:

```
auth.users (Supabase Auth 로그인 계정)
   │
   ├── public.user.user_id      ─→ 로그인 후 프로필(이름/역할) 조회용
   │
   └── counselors.auth_user_id  ─→ 담당 고객 소유권(counselor_id) 판별용
           │
           └── counselors.id  ←── clients.counselor_id / sessions.counselor_id
```

이 세 연결(`public.user`, `counselors.auth_user_id`, `clients/sessions.counselor_id`) 중 하나라도 빠지면, 로그인은 되지만 목록이 비거나 등록이 RLS 에러로 막히는 식으로 증상이 다르게 나타난다.
