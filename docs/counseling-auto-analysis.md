# 상담 종합 분석

상담 상세의 ‘요약 및 분석’ 탭 상단에서 등록정보, 전체 상담이력(날짜순), 문항별 설문 응답, 저장된 문서 추출정보를 종합한다. 파일을 추가하지 않아도 상담 기록으로 분석할 수 있다. 원문 첨부파일 자체를 새 함수에 전송하지 않는다.

- 결과: 종합요약, 강점, 장애요인, 상담 변화, 다음 상담 과제, 추가 확인 사항. 항목별 근거 날짜를 표시한다.
- 탭 진입/창 포커스/문서 분석 저장 후 최신 자료를 확인한다. 자료+모델+프롬프트 버전 해시가 같으면 저장된 결과를 재사용한다. 재분석 버튼은 30초 간격이다.
- 오류는 화면에 표시하고, 이전 결과가 있으면 이전 결과임을 명시한다. 정형 문구로 AI 성공을 가장하지 않는다.
- 기본정보에서 이름·전화·주소·주민번호 열을 분석 입력에서 제외한다. 자유문장의 대상자 이름·일반적인 전화/이메일/주민번호 형식을 가린다. 임의 서술문에서 개인정보가 완전히 제거됨을 보장하지는 않는다.
- 설문 1/2/3은 아니오/보통/예. 지원 필요도와 강점을 구분한다. 총점을 취업역량으로 사용하지 않는다. 기존 학력·자격 점수는 별도 참고점수로 표기한다.

## 구성

`analyze-client-counseling` 함수가 사용자 JWT를 검증하고 담당자/관리자 권한을 직접 확인한 뒤 사용자 RLS로 원본을 읽는다. 외부 AI 호출은 서버의 `OPENAI_API_KEY`만 사용한다. `COUNSELING_ANALYSIS_MODEL` 기본값은 기존 앱과 같은 `gpt-4o-mini`다. 결과는 서버만 쓰기 가능한 `client_counseling_analysis`에 저장한다.

`client_summary_analysis`는 기존 문서 분석용 저장소로 UUID `clients.id`를 참조한다. 기존 정수 ID 스키마를 가진 환경에는 SQL을 무작정 적용하지 말고 데이터를 확인한 후 별도 이관해야 한다.

최대 2,000개 상담/설문 행과 120,000자 입력 제한을 넘으면 누락 요약 대신 오류를 반환한다. 동시 요청 병합은 실행 인스턴스 안에서만 보장된다. 대규모 운영 시 프로젝트 수준의 사용량 제한/분산 잠금이 추가로 필요하다.

## 적용 상태 (2026-10-07)

- ZeniManager-Test에 UUID 분석 저장소와 RLS 적용 완료.
- 서버 함수 배포는 자동 승인 검토에서 외부 AI로 보내는 자료 범위에 대한 명시적 동의가 필요하다는 이유로 차단됨. 배포 전 사용자 확인 필요.
- GitHub 변경을 반영한 앱 빌드가 있어야 새 화면이 표시됨. 기존 설치된 Windows 앱에는 코드 변경이 자동 적용되지 않음.
- 신규 서버 분석 경로는 PC의 OpenAI 키를 사용하지 않는다. 기존 첨부문서 추출 경로의 로컬 API 키/파일 저장소 구조는 이번 변경에서 교체하지 않았다.

## 검증

대상 테스트: 원본 해시 변경·삭제 감지, 개인정보 필드 제외, 잘못된 근거 거부, 로그인·담당자 검사, 중복 요청 병합, 외부 AI 실패 시 저장 금지, 캐시 재사용. DB 검증은 트랜잭션 롤백으로 실제 응답을 남기지 않는다. 실제 외부 AI 호출은 배포 승인 전 실행하지 않는다.

검증 결과: 관련 테스트 17개 통과, 앱/Edge TypeScript 검사 통과, Vite 프로덕션 빌드 통과. 빌드에는 기존 analytics 환경변수 미설정 및 번들 크기 경고가 남아 있다. 브라우저와 실제 AI를 연결한 검증은 배포 승인 후 수행해야 한다.
